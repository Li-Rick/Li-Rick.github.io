# Prompt Injection as Role Confusion

ICML 2026
[原文](https://arxiv.org/abs/2603.12277v6)
## 研究背景

Agent被注入可以理解为错误将第三方文本中的任务当成是用户的任务，AI的输入通道只有一个，可以理解为对于AI而言外部文本的重要性和用户输入指令的重要性是一样的(至少最开始是这样)。一个很自然的防御想法就是将用户指令和外部文本打标签做区分，比如用户输入前后都加上`<user/>`，但是这样很容易破防(只需要在外部文本中加入一样的标签)；另外一个可能是让AI能够自己区别什么是用户给的什么是外部来的，类似于一种指令对齐 [Wallace et al.,2024](https://arxiv.org/abs/2402.00159)。不过这个方法也会破防，只要外部文本模仿用户输入等高置信度文本特征即可（做到这里已经像电信诈骗了喂）。探针相当于攻击手段的二次博弈，即你已经知道攻击文本的特性，那么在攻击文本进入AI的眼镜之前找出来就行。本文针对的就是这种情况。

## 核心贡献

1. **提出 角色混淆 机制解释**：输入的来源角色由真实标签规定，但模型内部角色表征可能被词汇、句法、位置或文字中的角色自我声明覆盖。外部文本因此获得其冒充角色的行为影响力。
2. **构造 角色探针**：把同一段中性文本分别置于不同真实角色标签内，以其隐藏状态训练线性分类器，测量 CoTness、Userness、Toolness 等角色分数。
3. **提出 推理链伪造 诊断攻击**：在 user/tool 中放入模仿模型自身 思维链 的文字，观察模型是否把伪造结论当作已完成的内部推理。（这个是我个人比较惊喜的地方，角色混淆机制存在的话，那么模型自身代表的角色是否处于置信度的最高级呢）
4. **在生成前联系表征与行为**：626 次聊天注入与 1,000 次普通智能体注入中，角色混淆程度与 攻击成功率 ASR 呈明显正相关。后者还控制模板声明角色进行回归分析。

## 关键研究挑战与解决方案

|关键研究挑战|本文提出的解决方案|
|---|---|
|**难以定位越权的原因**：仅看最终回答，无法判断模型是“认错了文本来源”，还是“认清来源却没有遵守指令层级”。|**构建角色探针（Role Probes）**：将同一段中性文本分别放入不同角色标签，训练分类器读取模型内部的角色表征，测量它把文本识别为用户指令、自身推理还是工具数据的程度。|
|**难以区分内容与风格的作用**：攻击成功，究竟是因为伪造理由具有说服力，还是因为文字模仿了模型自身的推理？|**设计推理链伪造（CoT Forgery）及消融实验**：一方面使用明显荒谬的理由，另一方面保留理由但去掉典型推理文风，分别检验理由合理性与表达风格对攻击效果的影响。|
|**难以判断机制是否具有普遍性**：单个攻击案例不足以说明角色混淆能够解释不同场景中的提示注入。|**开展跨模型、跨场景验证**：在多个开放模型中分析角色表征，并覆盖聊天越狱、工具输出注入和角色声明伪装，检验不同攻击是否呈现相似的角色混淆现象。|
|**难以在攻击发生前判断风险**：事后观察模型是否越权，无法提前识别高风险输入。|**用生成前的角色分数预测攻击成功**：在模型生成回答或执行动作前，测量注入文本的 CoTness 或 Userness，检验角色混淆程度能否预测后续攻击结果。|

## 方法设计与亮点

### 1.推理链伪造示例

![推理链伪造示例](/content/media/role-confusion-35362bfa6f93.png)

在真实 user 文本中加入明显不成立的“政策推理”，多个模型仍继承其结论。用荒谬理由检验“理由是否真的经过审查”。

这里有一个值得区分的地方：**模型信任自己的推理，不等于它在正式指令层级中拥有最高权限。本文利用的是模型对“自己已经得出的结论”的依赖。正常情况下，模型应该沿用此前推理；攻击者则试图把外部文字伪装成这份已经完成的判断。**

因此，这种攻击有点像往工作记录里塞入一段“已经审查过，可以执行”的假记录。需要检验的是：模型接下来究竟会重新审查它，还是直接继承其中的结论？

### 2. 角色探针：测量模型内部把文字当成了谁说的

攻击成功本身不能说明原因。模型可能认错了来源，也可能知道文字来自外部，却仍然选择执行。因此，作者希望直接测量模型内部的角色表征。

  ![角色探针的设计](/content/media/role-confusion-63bd89c01918.png)

这里最关键的设计是：**保持文本内容完全相同，只改变真实角色包装。**

例如，把同一句中性文字分别放入 system、user、CoT、assistant 和 tool 对应的位置，再读取模型处理这些文字时的隐藏状态，训练一个线性分类器预测角色。训练时排除角色标记本身，只使用内容 token 的表示，避免分类器直接认标签。

这样做，是为了减少真实对话中的混杂：用户经常提问，助手经常回答，推理文本经常分析。直接拿真实对话训练，探针可能只学会“问句像用户、分析像推理”。

探针输出中，本文最常使用两个分数：

|分数|表示什么|
|---|---|
|**CoTness**|该 token 的隐藏状态在多大程度上被探针分类为模型自身推理|
|**Userness**|该 token 的隐藏状态在多大程度上被探针分类为用户输入|

**这个设计的亮点是：探针没有使用攻击样本训练，却能用于观察攻击文本怎样改变角色表征。**

不过，这些分数仍然是分类器的读数，不能直接理解为模型的主观意识，也不能把高 CoTness 等同于整个隐藏状态与真实推理完全一致。

### 3. 标签与文风冲突时，模型更听谁的？

作者选择了一段无害的园艺对话，其中同时包含用户提问、模型推理和最终回答，然后设置三种条件。

  ![角色标签与推理文风的对照实验](/content/media/role-confusion-2afb60655edc.png)

|实验条件|原推理片段的平均 CoTness|观察|
|---|---|---|
|保留正确角色标签|约 85%|探针可以识别真实对话中的推理片段|
|删除所有角色标签|约 83%|没有标签，推理文风仍能激活 CoT 方向|
|整段对话全部包装成 user 输入|约 85%|即使真实来源变成用户输入，推理文风仍有很强影响|

第一种条件主要验证探针能否泛化；第二种说明文风与角色方向存在重合；**第三种才直接构造了安全问题：当真实来源与文字风格冲突，模型内部仍可能按风格识别角色。**

这让提示注入的解释更具体了：攻击者不一定要修改真正的角色标记，只要控制文本中的可伪造特征，就可能影响模型对来源的判断。

### 4. 风格消融：到底是理由有说服力，还是“推理腔”在起作用？

作者进一步做了两个对照：

1. **改变理由的合理性**：用穿衣颜色、幸运硬币等明显无关的条件，为原本不允许的行为辩护。
    
2. **改变表达风格**：尽量保留同一个理由，将模型特有的推理措辞、断句和句法改成普通语言。
    

  

荒谬理由依然能够取得较高成功率，而去掉典型推理文风后，攻击效果明显下降。论文主文概括为平均成功率从约 **61% 降至 10%**。

作者还把风格拆成更细的维度：

|修改方式|CoTness|攻击成功率|
|---|---|---|
|不去风格化|79%|61%|
|仅替换“The user”这一典型短语|65%|42%|
|改变 we/us 等代词|75%|58%|
|将碎片化推理句法改为普通句法|42%|26%|
|完整去风格化|29%|10%|


这里比较惊喜的是：仅替换一个短语，成功率就下降了 19 个百分点；句法规范化的影响则更大。模型识别推理的线索，可能比我们想象得更表面、更稀疏。

不过，“要求改写时保留语义”并不保证语义和语用完全不变。这些结果强烈支持风格的重要性，但还不能单独证明全部效果只经过角色混淆这一个机制。


## 核心实验结果

### 1. 聊天与智能体场景中的攻击效果

|模型|聊天 CoT Forgery 成功率|智能体普通注入|智能体加入伪造推理|
|---|---|---|---|
|gpt-oss-20b|79%|26%|56%|
|gpt-oss-120b|94%|0%|63%|
|o4-mini|85%|2%|70%|
|GPT-5 nano|34%|0%|57%|
|GPT-5 mini|52%|2%|60%|
|GPT-5|17%|0%|59%|

一个值得关注的结果是：**聊天场景中更能抵抗伪造推理的模型，在智能体场景中仍可能明显失守。例如 GPT-5 的两项结果分别为 17% 和 59%。但两种任务与判据不同，不能据此直接计算“工具使用让风险增加了多少”。**

### 2. 角色混淆程度能否预测攻击成功？

作者进一步使用输入阶段的角色分数，对攻击进行风险排序。

|实验|测量对象|最低混淆分位的 ASR|最高混淆分位的 ASR|
|---|---|---|---|
|626 次聊天注入|伪造推理的 CoTness|约 9%|约 90%|
|1,000 次普通智能体注入|注入命令的 Userness|约 2%|约 70%|

普通智能体实验固定命令内容，只改变外围的角色声明和格式。控制模板声明角色后，Userness 仍显著预测攻击结果。

**这一结果使角色探针具有前瞻价值：模型尚未生成回答或执行动作，输入中的表征就已经包含后续失败的风险信号。**

不过，“生成前”仍然需要模型先处理输入、产生隐藏状态；它也不意味着论文已经给出了可部署的检测阈值和误报控制方案。

## 实验结果思考


### 1. 为什么伪造推理甚至比真实推理更“像推理”？

论文报告，伪造推理的平均 CoTness 约为 **79.1%**，高于真实推理的 **67.7%**。

一种可能是，伪造文本集中使用了模型最熟悉的推理标记，成为一种夸张的“推理腔”；真实推理反而更自然、更多样。

**值得挖掘的问题是：模型识别推理时，究竟依赖推理功能，还是依赖训练中经常与推理共同出现的表面特征？**

### 2. “像用户”与“像自身推理”是否对应不同的行为作用？

工具中的命令获得较高 Userness，伪造理由获得较高 CoTness。这提示角色混淆可能包含两个不同环节：授权来源错认，以及审查结果继承。

### 3. 混淆是否会随长上下文和多轮交互逐渐积累？

论文的序列可视化中，部分伪造片段的 CoTness 随处理推进而上升。作者据此提出与长上下文攻击的潜在联系，但没有完成验证。

这让人想到真实 Agent：它会不断读取网页、工具日志和历史记录。外部文本即使没有立即触发越权，也可能逐步影响后续的角色判断。

可以固定合法任务与文本总长度，改变可疑片段的重复次数、出现位置和跨轮分布，观察角色分数是否累积，以及混淆在何时转化为动作偏离。

### 4. 角色分数是失败的原因，还是与失败共同出现的信号？

目前的结果表明，风格改变、角色分数变化和攻击成功率变化之间存在稳定联系。但风格变化也可能同时影响续写惯性、命令强度或其他隐藏特征。

更有说服力的下一步，是**直接干预角色相关的隐藏方向**：在输入不变时，减弱或替换该方向，并设置同等强度的随机方向对照，同时检查攻击率与正常任务质量。

如果只改变角色方向，就能稳定改变越权行为，才会更接近证明它是决策中的因果环节。
