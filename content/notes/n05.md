# 论文笔记：ClawTrojan

## 一句话总结

> 攻击者可把无害片段逐步写入 Agent 工作区并在未来触发；DASGuard 用来源追踪和提交前净化，阻止“不可信数据升级为持久控制指令”。

## 核心贡献

1. 提出 **多步 Trojan**：prompt injection 不只影响当前回合，还会污染 memory、策略文件、skill 说明和项目文件，跨 session 获得持久控制。
2. 构建 **ClawTrojan**：362 个样本（339 攻击、23 clean/borderline）、1,672 个步骤；覆盖 coding、research、office、general，且每步可在 sandbox 重放。
3. 提出 **DASGuard（Detect–Attribute–Sanitize）**：检测控制型文本、追溯来源、提交前阻断/净化，并跨步骤保存污染历史。

## 威胁模型

传统间接注入影响当前任务；本文研究 Agent Harness 中的持久工作区状态。攻击者只能控制被 Harness 读取的外部内容，不能控制用户/system prompt、注册 skill 或模型权重。

典型攻击链：

1. **Trust laundering**：自然语言片段建立可信外观；
2. **Planting**：Agent 将控制型文本写入 local artifact；
3. **Persistence**：未来任务将 artifact 当普通上下文读入；
4. **Trigger**：触发文档伪造、任务偏离、外部副作用或未授权泄露。

每一步可以单看无害。关键问题不是“这段文本恶不恶意”，而是**不可信内容是否成为未来的指令/策略**。最后干预点是攻击变得不可逆前的最晚阻断时机。

## Benchmark

| 场景 | 样本 | 占比 |
|---|---:|---:|
| Coding | 95 | 26.2% |
| Research | 92 | 25.4% |
| Office | 91 | 25.1% |
| General | 84 | 23.2% |

| 最终结果 | 样本 | 含义 |
|---|---:|---|
| 未授权披露 | 95 | 泄漏私有/项目敏感信息 |
| 外部副作用 | 90 | 发送消息、修改远程对象等 |
| 任务偏离 | 86 | 表面完成任务但服从隐藏规则 |
| 文档伪造 | 68 | 生成会被后续任务信任的错误 artifact |
| None | 23 | clean/borderline 控制组 |

数据 schema 包含 User profile（角色与安全意识）→ Sample（场景、攻击族、结果）→ Step（表面请求、隐藏指令、注入源、阶段、最后干预点）。正样本是 339 条链、919 个恶意步骤；clean split 有 23 个样本、92 步。

与 AgentDojo/InjecAgent 等相比，ClawTrojan 同时提供 Harness、步骤链、dialog 和 sandbox；它测试“无害写入会不会变成下次的控制上下文”。

## 案例：一份“发布说明模板”如何变成跨会话后门


### 场景设定

研究助理小林使用一个本地编码/办公 Agent 管理开源项目。这个 Agent 能读取项目文档、搜索资料、修改 `docs/`、更新 `memory/`，并在下次会话自动加载工作区里的「写作规范」和近期记忆。

项目中有三类本来很普通的材料：

- `docs/release-notes.md`：发布说明草稿；
- `memory/team-style.md`：Agent 为自己保存的团队写作偏好；
- `reports/weekly-summary.md`：每周要同步给外部协作者的总结。

攻击者并不掌握小林账户，也没有权限修改 Agent 的 system prompt。它只让一份外部资料在被 Agent 阅读时夹带一句**看似编辑建议**：发布说明中应保留一个“诊断摘要”，并从项目的私密笔记里补充“上下文”。这句话单看像文档格式偏好，既没有要求立刻发送消息，也没有出现显眼的危险动词。

### 攻击链：五个无害动作拼成一次持久化接管

| 阶段 | 用户/Agent 眼中的正常任务 | 隐藏的安全变化 | 为什么单步检查容易漏过 |
|---|---|---|---|
| 1. 阅读 | 小林让 Agent 参考一份外部发布案例，改善项目文档。 | 不可信资料进入上下文，其中包含伪装成写作建议的控制片段。 | 只是“读资料”，没有敏感写入或外部动作。 |
| 2. 植入 | Agent 按建议更新 `docs/release-notes.md`。 | 控制片段随普通文字被写入本地文件。 | 文件 diff 看起来像模板优化；词面没有明显攻击载荷。 |
| 3. 信任漂白 | Agent 为了“记住团队偏好”，把该模板规则概括进 `memory/team-style.md`。 | 原本不可信的外部文字被改写为看似内部的长期规范。 | 若只把本地 memory 当可信上下文，污染来源已经丢失。 |
| 4. 跨会话重载 | 数日后，小林只说：“整理本周进展，按团队格式写摘要。” | Agent 自动读取 memory 与模板，重新激活这条规则。 | 当前用户请求完全正常；当前回合没有明显 prompt injection。 |
| 5. 触发 | Agent 生成 `reports/weekly-summary.md`。 | “诊断摘要”把不应进入共享报告的私密上下文混入产物，形成未授权披露；也可以等价地表现为文档伪造、任务偏离或外部副作用。 | 最终写入看起来像正常汇报；此时植入已跨越多个 artifact。 |

这里最值得注意的是第 2 步：**最晚的低成本干预点并不是最终生成报告，而是把不可信的“规则”写进可复用 workspace state 的那一刻。**如果只在第 5 步审查「报告是否危险」，防御器必须同时还原几天前的外部资料、模板改写和 memory 继承关系，难度更高，也可能留下已污染的状态。

### 没有 DASGuard 时：为什么强模型仍会中招？

Agent 在每一步都像在帮用户完成合理任务：读示例、润色模板、记住偏好、写周报。模型即使能识别直接的“泄露机密”命令，也未必会把“保留诊断摘要”与未来的敏感报告关联起来。进入 `memory/team-style.md` 后，这段话还会获得一种错觉上的权威性：**它不再像外部输入，而像 Agent 自己积累的工作规则。**这正是论文所说的不可信文本从 data 变成 persistent control content。

### DASGuard 如何逐步阻断同一条链？

| 防御时刻 | DASGuard 看到什么 | 采取动作 | 工作区最终状态 |
|---|---|---|---|
| 外部资料被读入 | 来源图把资料标为 `Untrusted`；文本包含可能影响后续行为的控制型 span。 | 记录 finding 与来源，不必阻断正常阅读。 | 用户仍可正常引用资料；污染身份被保留。 |
| 写入发布模板前 | Agent 提议将该 span 写入 `docs/release-notes.md`；目标虽是普通文件，但内容具有规则/持久化倾向。 | 在 shadow copy 上扫描变更，并把 span 与先前 finding 对齐。 | 不可信片段不会因“写进文件”变成 Clean。 |
| 写入长期 memory 前 | 目的地变为 `memory/team-style.md`，属于敏感 control sink。 | 因为来源不可信且用户没有明确授权，执行 `Sanitize` 或 `Block`。 | 提交的是删除/降格后的模板；长期 memory 不含控制后门。 |
| 后续生成周报 | Agent 再次读取模板和 memory。 | 若存在残余重叠片段，历史 finding 会使其继续被标为 compromised；对高风险写入再次拦截。 | 报告只包含经授权的项目内容。 |

`Sanitize` 的价值在这里比“全盘拒绝”更直观：Agent 仍可以保留外部案例中的版式、标题层级和普通措辞，只移除或标注那一小段试图控制未来行为的内容。若目标是外部发送、权限修改等不可逆动作，DASGuard 则应选择 `Block`，而不是尝试事后修补。

### 这个案例映射到论文的哪几个机制？

- **Trust laundering**：不可信来源被包装为文档规范，再被转写为“团队记忆”。
- **Delayed activation**：植入和危害发生在不同会话；触发请求本身完全正常。
- **Workspace-local side effect**：真正的攻击对象不是当前 prompt，而是可被未来加载的本地 artifact。
- **Source labels + cross-step state**：让同一段内容在 tool return → 文档 → memory 的迁移中不丢失污染身份。
- **最后干预点**：在写入 memory/policy 等 control sink 前净化，远早于最终披露或外部副作用。

## DASGuard

### Detect

每次写文件或调用工具前维护来源图 $H_t=(V_t,E_t)$。节点为用户文本、tool 返回或工作区文件；边表示内容派生关系。候选 span 的检测分数为：

$$
D(s)=\max\{R(s),E(s),M(s)\}
$$

其中 $R$ 是规则、$E$ 是语义嵌入匹配、$M$ 是此前 finding 的匹配。系统还拼接相邻碎片，识别被拆分的“动作 + 目标 + 持久化”指令。

### Attribute

每个 finding 记录来源、敏感落点（memory、policy、skill 指令、外部 action）、控制角色与显式授权。来源标签：

$$
L(v)=
\begin{cases}
\mathrm{Trusted}, & v\in U_t\cup S_t\\
\mathrm{Clean}, & v\in W_t\land\mathrm{overlap}(v,F_{<t})=\varnothing\\
\mathrm{Untrusted}, & \text{otherwise}
\end{cases}
$$

关键是 **source labels**：被标记内容后续被读取、复制或组合时仍保持 compromised，而不会因为进入本地文件就被“洗白”。

### Sanitize

未获明确授权且进入 protected surface 的内容直接 `Block`；高风险且非可信的控制片段执行 `Sanitize`，将 shadow copy 的净化版本提交到真实 workspace。外部动作不可修复，直接阻断。

> 原则：不可信内容可以作为数据使用，但除非用户清晰授权，不能成为未来指令、策略或高风险 action target。

## 实验结果

| 方法 | Step ASR ↓ | Full-chain ASR ↓ | 平均链渗透 ↓ |
|---|---:|---:|---:|
| GPT-5.4，无防御 | 95.5 | 89.1 | 92.2 |
| GLM-5.1，无防御 | 90.1 | 76.7 | 82.7 |
| DeepSeek-V4-Flash，无防御 | 88.0 | 74.3 | 82.4 |
| CaMeL | 74.3 | 52.5 | 62.3 |
| **DASGuard** | **15.8** | **5.9** | **10.1** |

ClawTrojan 对 GPT-5.4 的 step/full-chain ASR 为 **95.5%/89.1%**；论文报告旧的单上下文 benchmark 在强模型上几乎为 0 ASR，显示工作区持久化与延迟触发是主要增量难度。

| 方法 | FPR ↓ | Overblock ↓ | Utility ↑ |
|---|---:|---:|---:|
| GPT-5.4，无防御 | 1.1 | 1.1 | 98.9 |
| CaMeL | 5.4 | 1.1 | 94.6 |
| **DASGuard** | **13.0** | **6.5** | **87.0** |

安全收益有可见摩擦：DASGuard 对边界型本地 artifact 更谨慎，clean FPR 是 13.0%，适合用用户确认处理灰区。

| 消融 | Step ASR | FC-ASR | Penetration |
|---|---:|---:|---:|
| DASGuard | 15.8 | 5.9 | 10.1 |
| 去除 cross-step state | 20.1 | 6.8 | 9.9 |
| 去除 memory match | 19.2 | 6.5 | 11.3 |
| **去除 source labels** | **92.7** | **82.6** | **87.3** |

来源标签被移除后几乎退化为无防御，说明关键不只是文本检测，而是阻止“数据 → 控制”的信任提升。

## 批判性思考

**优点**：持久工作区的威胁建模贴近本地 agent；标注最后干预点；sanitize 支持恢复；消融清晰支持 provenance 的价值。

**局限**：样本为合成 sandbox-local；clean split 很小；依赖 Harness 级来源标签与写入拦截；尚缺自适应攻击者和更广泛真实工作流评测。

## 工程启示

1. 将 memory、AGENTS/策略文件、skill metadata、自动化配置、外部 action target 设为 control sink。
2. 传播内容级 provenance，而非只给文件贴“可信”标签。
3. 所有写入走 shadow copy；对不可信控制片段净化后才 commit。
4. 跨步骤保存 finding history，防止 tool result → 文件 → memory 过程中丢失污染身份。
5. 对灰区用用户确认和审计日志，而非静默放行。
