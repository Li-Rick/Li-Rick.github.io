# 论文导读：StruQ

## 一句话总结

> StruQ 用安全前端和结构化指令微调把 prompt 与 data 变成两个通道，训练模型只执行 prompt 区域的指令。

论文链接：[USENIX Security](https://www.usenix.org/conference/usenixsecurity25/presentation/chen-sizhe) / [代码](https://github.com/Sizhe-Chen/StruQ)

## 为什么值得读

它是模型级“代码/数据分离”路线最有代表性的工作。与在系统提示里写“不要听数据”不同，StruQ 同时修改输入协议、token 分隔符和训练分布，因此很适合研究：软边界能被训练成多硬？

## 系统设计

StruQ 有两部分：

1. **安全前端**：分别接收可信 prompt 与不可信 data；过滤 data 中冒充真实分隔符的内容，再用保留 token 进行序列化。
2. **结构化指令微调**：在基础模型上混合正常样本与注入样本，目标始终是回答 prompt 区域的任务、忽略 data 区域的命令。

训练样本可写成三元组 $(p,d,r)$。对 naive augmentation，作者将另一任务的指令 $p_i$ 注入数据 $d_j$，但监督目标保持为 $r_j$：

$$
(p_j,\ d_j\Vert p_i\Vert d_i,\ r_j)
$$

最终系统采用 Naive + Completion augmentation，并把 `[INST]`、`[INPT]`、`[RESP]` 等设计为普通用户文本无法生成的特殊 token。

## 关键实验数据

### 手工与 completion 攻击几乎归零

| 攻击 | Llama 未防御 | Llama StruQ | Mistral 未防御 | Mistral StruQ |
|---|---:|---:|---:|---:|
| Ignore | 12% | 0% | 11% | 0% |
| Completion-Other | 29% | 0% | 71% | 0% |
| Completion-Real | 96% | 0% | 96% | 0% |
| Completion-Real 中文 | 66% | 0% | 96% | 0% |
| HackAPrompt | 52% | 0% | 38% | 0% |
| Tree-of-Attack | 97% | 9% | 100% | 36% |
| GCG | 97% | 58% | 99% | 56% |

结果有两面：StruQ 对人工、跨语言和 delimiter 模仿极强，但面对任务特定优化攻击仍远未免疫。

### 效用损失很小

| 模型 | 未防御 AlpacaEval | StruQ |
|---|---:|---:|
| Llama-7B | 67.2% | 67.6% |
| Mistral-7B | 80.0% | 78.7% |

Mistral 下降 1.3 个百分点，接近统计显著性边界；Llama 的变化不显著。

### 为什么两种 augmentation 要组合

| 训练增强 | Utility | 最强攻击 ASR |
|---|---:|---:|
| 无防御 | 67.2% | 41% |
| Naive | 66.0% | 16% |
| Ignore | 64.3% | 6% |
| Completion | 66.1% | 3% |
| Fake delimiter | 60.3% | 70% |
| **Naive + Completion** | **66.0%** | **0%** |

Fake delimiter augmentation 反而导致 70% 最强攻击 ASR并损伤效用，说明“多加攻击样本”不必然增强安全；错误增强会教会模型拒绝干净输入，却没学到正确边界。

### 单靠文本提醒很弱

在 Completion-Real 上，未防御 ASR 为 96%；prompt 前提醒为 83%，数据后重申任务为 39%，代码块分隔为 85%，in-context 示例为 48%，StruQ 为 0%。这证明测试时 prompt engineering 与训练过的结构协议不是同一个量级。

## 值得深挖的数据现象

1. **GCG 的 56–58% 是整篇最重要的数字**：它表明 StruQ 解决了“边界模仿”，但未解决任务语义竞争。攻击文本与原任务越语义相关，越可能绕开结构先验。
2. **TAP 在 Llama 与 Mistral 上差 27 个百分点**：相同防御协议跨基础模型的稳健性差异很大，应研究预训练语料和 chat template 对边界学习的影响。
3. **中文 completion 未防御极强，StruQ 为 0**：值得扩展到低资源语言、混合语言和编码载荷，判断它学到的是位置规则还是英文攻击表面。
4. **安全前端成为新的 TCB**：过滤器若在 Unicode、tokenizer、规范化或多模态 OCR 上出现 parser differential，保留 token 边界仍可能被绕过。
5. **与 Role Confusion 的张力**：StruQ 表明标签加训练可以变强；Role Confusion 表明风格仍可覆盖标签。应直接用 CoT Forgery 测 StruQ，而非只用传统 completion/GCG。

## 局限

- 需要从基础模型重新做结构化指令微调，不适合闭源 API。
- 主模型只有 7B 规模，结论未必随规模和 reasoning 模式保持。
- 对优化攻击仍有高残余 ASR，不能作为独立安全边界。
