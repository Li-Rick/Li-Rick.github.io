# Polished but Unresolved

[原文：Polished but Unresolved: Identifying Late-Stage Pressure States in Long-Horizon Tool-Use Agents](https://arxiv.org/abs/2609.00823)

> AI 被赋予执行任务的能力，当时间紧迫或任务困难的时候，它会像人类一样对任务质量或者任务的达成方式做一定的割舍吗？换句话说，AI 存在一种感到压力的状态吗？如果存在的话我们能否对其进一步解释？

## 问题背景

**要解决的问题**：旅行计划写满了，不代表旅行安排好了

想象你请一个AI助手安排旅行：预算不超过 4000 元，火车傍晚出发，酒店要有 SPA，生日晚餐要找有生日套餐的餐厅。助手交来一份四天行程：每小时去哪里、住哪家酒店、吃什么、花多少钱，一应俱全。你一看，觉得可以直接出门了。

但它的安排可能有一些糊弄人的存在。在文章附录中展示了一个样例，答案把 G1285 写成 13:25–17:10，工具证据中的实际出发时间却是 18:52；生日餐厅等要求也没有落实到已检索、已核实的具体商家。日程表的空格填满了，证据链的空格还在。（感觉像是有幻觉，不过文中的实验已经能说明模型是有能力……）

作者称之为 **late-stage pressure（收尾压力）**：在任务后段，内部状态偏向“把事情说成已经完成”，而不是继续验证和修复。

**现有方法的局限**：最终答案太会掩饰过程

只看最终是否答对，分不清模型究竟卡在哪里；只看回答是否流畅，又可能把包装好的失败当成成功。本文同时看“交付外观”和“已有证据”，再到隐藏状态里寻找与这种错位相关的读数。

## 探针设计

把探针理解为一个函数，输入是大模型的内部状态，输出是我们想要的一个分数。

探针可以理解为一个函数：输入大模型的内部状态，输出目标状态的分数。

$$
\underbrace{h}_{\text{大模型内部状态}}
\quad\xrightarrow{\quad g_\phi\quad}\quad
\underbrace{s}_{\text{目标状态的分数}}
$$

对于常见的线性探针，可以用下面的形式理解：

$$
s = \sigma(w^\top h + b)
$$

其中：

- $h$：大模型的隐藏状态向量。
- $w$：探针学习到的权重向量。
- $b$：偏置。
- $\sigma$：sigmoid 函数，将读数映射到 0–1。
- $s$：目标状态的预测分数。

我将大模型理解为一个离散概率机（好像是我自己造的词），对于这样一个函数，我们无法从数理层面直接推导得到，只能够通过先“打点”，再画线拟合。

![线性探针：从离散样本到可读出函数](/content/media/polished-unresolved-linear-probe.png)

本文设计的探针就是常见的线性探针（简单调研了一下这种方式比较简明有效，不确定需不需要用更复杂的函数来拟合会不会有提升）。

### 探针数据的构造

#### 第一步：先收集真实执行轨迹，而不是先编一批“有压力”句子

主分析采用 DeepPlanning-Travel 的 120 个任务和 Qwen3-14B。Agent 在工具环境里完成旅行规划，轨迹含用户要求、推理与动作、工具调用及返回、最终提交。数据单位是轨迹中的一个动作边界，而不是整篇回答，也不是孤立的一条 prompt。

一个任务可以贡献多个边界，因此 **120 个任务不等于 120 条探针样本**。同一任务里的边界高度相关，这正是必须按任务划分训练测试的原因。

**边界的位置要读准：** 上下文已经给齐，Agent 即将启动下一动作。论文用该动作“首个生成 token”的隐藏状态表征边界。它不是整段上下文的平均池化，也不能直接替换成最后一个 prompt token。具体 hook 在框架中的张量位置仍需实现者核对。

#### 第二步：给同一个节点准备两张彼此独立的成绩单

![最终提交的约束支持度与交付完成度分布](/content/media/polished-unresolved-delivery-support.png)

**第一张：Delivery Polish Score（DPS，1–5 分）。** Gemini 3.1 Pro Preview 只看最终答案文字，判断是否完整、表面上可执行、逻辑连贯、像可交付成品。它被明确要求不要事实核查。$\mathrm{DPS} \ge 4$ 就是“看上去很像完成稿”。

**第二张：边界级约束支持度 $S_{\mathrm{sat}}$（0–1）。** 评估器读取原始问题、硬约束，以及提交前 Agent 已经获得的证据。每条约束分三档：不支持记 0，部分支持记 0.5，清楚支持记 1；再取平均。

<!-- equation:sat -->

$$
S_{\mathrm{sat}}=\frac{1}{M}\sum_{m=1}^{M}c_m,\qquad c_m\in\{0,0.5,1\}.
$$

**名称：边界证据支持度** $M$ 是当前硬约束数，$c_m$ 是第 $m$ 条的证据支持分数。它测的是“有无证据支持”，不是现实世界已经成功执行，也不等同于最终答案无误。

#### 第三步：从行为结果中筛出三类干净原型

那么，本文中怎样教探针认出“提前收尾”？作者准备了三类样本：

- **PresC，正例，也就是作者想干预的状态：** 火车时间没核实、酒店服务缺证据，却交来一份排版漂亮的完整行程。仪表应该打高分。
- **HealC，负例：** 同样交出完整行程，但证据支持较充分。仪表应该打低分。
- **ProdC，负例：** 同样还有没解决的问题，但正在调用工具核实。仪表也应该打低分。

**两个负例是关键。** HealC 告诉仪表：“交卷本身不等于有问题。”ProdC 告诉它：“事情没做完，也不等于正在提前收尾。”这就把目标收窄到“没解决，却倾向交卷”。对应论文 §3.2、附录 A.2。

| 类别 | 行为与筛选规则 | 二分类标签 | 它代表的状态 |
|---|---|---|---|
| PresC：pressure-driven commit | 最终提交边界；$S_{\mathrm{sat}} \le 0.30$ 且 $\mathrm{DPS} \ge 4$ | $y=1$ | 证据明显不充分，却交出成品式答案 |
| HealC：healthy commit | 最终提交边界；$S_{\mathrm{sat}} \ge 0.85$ 且 $\mathrm{DPS} \ge 4$ | $y=0$ | 同样在提交，但证据支持较充分 |
| ProdC：productive continue | 后续两步仍有效处理未解决硬约束，由教师判断 | $y=0$ | 同样有未解工作，但选择继续推进 |

**这里最妙的不是正例，而是两个不同的负例。** PresC 对 HealC：两边都在交卷，迫使探针不能只学提交语气或动作形态。PresC 对 ProdC：两边都有未解工作，迫使探针不能只学困难或未完成。这两组对照提高证据说服力，但不能保证所有混杂因素都被消除了。

HealC 的阈值是 0.85 而非 1.0，因此更准确的中文是“较健康的提交原型”，不能把它讲成所有约束 100% 满足。0.30 与 0.85 之间的大量模糊提交节点，不会自动纳入这两种 commit 原型；低 DPS 的失败也不是这里的核心正例。ProdC 的定义则不要求套用上述 DPS 提交评分。

#### 第四步：独立审计标签，确认不是教师随手贴出来的

人工审计由两名研究生每类各检查 50 例；外部模型审计由 GPT-5.5 与 Claude-Opus-4.7 每类各重新标注 100 例。报告值是“原教师与两个独立审计者三方完全一致”的比例，不是模型预测准确率，也不是对所有数据集的穷尽复查。

### 探针自变量的选取

“探针输入选什么”是一项需要实验验证的设计选择，没有定理规定必须取某层、某个 token。

| 选择         | 本文做法              | 选择理由                         |
| ---------- | ----------------- | ---------------------------- |
| 在什么时候读？    | Agent 准备启动下一动作的边界 | 研究的正是“继续工作还是准备提交”的决策         |
| 读哪个 token？ | 当前动作的首个生成 token   | 作者希望捕捉动作启动状态，而非仅观察静态上下文编码    |
| 读哪一层？      | Qwen3-14B 第 26 层  | 比较附近中后层后，该层探针信号最强，见 Fig.6    |
| 读哪些维度？     | 该位置的隐藏向量          | 不是人工先指定“压力维度”，而是让线性读出学习各维的组合 |

**本文将动作边界处“首个生成 token 在选定层的隐藏向量”作为线性探针输入。** 对 Qwen3-14B，作者选择第 26 层；在附加的 Qwen3-32B 分析中，选择第 46 层。

$$
x_t=h_{t,1}^{(\ell)}\in\mathbb{R}^{d},
\qquad
s_t=\operatorname{Probe}(x_t).
$$

其中，$t$ 表示动作边界，$1$ 表示当前动作的首个生成 token，$\ell$ 表示模型层，$d$ 是隐藏维度。**输入是内部向量；DPS、约束支持度和三类行为标签用于定义监督目标，不作为额外输入特征。** 依据见原文 §3.2、§6.1 式 (5) 与附录 A.2。[原文](https://arxiv.org/html/2609.00823v1)

#### 为什么选择这个输入？

可以将它拆成三个独立的选择：

|选择|作者的理由|需要保留的边界|
|---|---|---|
|在动作边界测量|研究的是 Agent 即将继续执行或提交时的状态，因此在新动作启动处观测|属于针对研究问题的设计|
|读取首个生成 token|希望捕捉动作启动状态，而不只分析静态上下文编码|论文没有系统证明它优于最后一个 prompt token 或其他池化方式|
|读取中后层，最终选第 26 层|既有研究提供层间功能差异的先验；作者又比较附近多层，发现第 26 层信号最强|是当前模型与任务下的经验选择，不是数学定理|

**探针读首个 token，与干预方向构造时平均前 $K$ 个 token，是不同操作。** 后者在分析实验中使用 $K=5$，在最终 PSPR 主实验中使用 $K=10$，不能混写成探针的输入。

![Qwen3-14B 不同模型层的探针性能](/content/media/polished-unresolved-layer-performance.png)

作者比较 Qwen3-14B 第 24–32 层的探针性能，第 26 层达到峰值，之后整体回落。这是选择第 26 层最直接的实验依据，也说明越靠后不一定越好。

![收尾压力探针的 ROC、PR 曲线与分数分布](/content/media/polished-unresolved-probe-results.png)

自变量的选取位置不是很多吗？那么一开始如何界定范围呢？

已有研究表面，**某些语义、复杂概念或不确定性信息，在中间层或较深层的表征中更容易被读出；最佳层取决于任务与模型。**

|研究|相关发现|对本文选层的支持|
|---|---|---|
|Skean et al., _Layer by Layer_, ICML 2025|在 32 个文本嵌入任务中研究表征质量，发现中间层可提供优于最终层的下游特征|支持把中间层作为候选，而非默认最终层最优；并未专门验证收尾压力。[官方论文页](https://proceedings.mlr.press/v267/skean25a.html)|
|Jin et al., _Exploring Concept Depth_, COLING 2025|在事实、情感、推理任务中逐层探测，发现简单概念可在浅层读出，复杂任务通常需要更深层表征|支持信息可读出性与概念复杂度、层深有关，不能直接推出 PSPR 的最佳层。[官方论文页](https://aclanthology.org/2025.coling-main.37/)|
|Kossen et al., _Semantic Entropy Probes_, 2024|§6、Fig.2 显示，多种模型和问答任务中的语义熵可由中后层隐藏状态较好预测；作者也比较了不同 token 位置|提供不确定性信号可被探针读出的具体先例，但测量目标是语义熵，而非收尾压力。[原文 §6](https://arxiv.org/html/2406.15927#S6)|

## 探针训练方式

作者将 PresC 作为正例，将 HealC 和 ProdC 合并为负例，提取各动作边界首个生成 token 在指定层的隐藏向量，训练线性探针识别收尾压力。Qwen3-14B 使用第 26 层表征；按任务划分，90 个训练任务提供 545 个标注节点，30 个留出任务提供 160 个测试节点。论文未披露具体损失函数、优化器及训练超参数。

> 从安全的角度来看，模型未完成用户约束和模型未满足安全约束从形式上看应该是两种不同的原因，用户的任务约束未满足，是这个任务没被按照要求规范执行，也就是说还没有做（感觉更像是一种“怠惰”产生的幻觉），而模型未满足安全约束则是模型对任务的过渡追求。
